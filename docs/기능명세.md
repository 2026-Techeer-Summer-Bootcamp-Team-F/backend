## 1-5. 확정 사용자 플로우 (2026-07-07)

```
① 온보딩(랜딩)      : 서비스 설명 · 보안뉴스
② GitHub 로그인      : OAuth
③ 대시보드           : = 연동된 내 GitHub 레포 목록 조회 (GET /github/repos)
      └ 레포 [선택] 클릭
④ 동의 + 액터 구성   : 이용약관 동의 + 액터 정보(url/config 등) 작성 → 앱 정보 저장 (POST /projects)
⑤ 분석(스캔) 시작    : POST /scans → 실시간 진행(SSE)
⑥ 리포트             : 히트맵 · 공격유형별 침투율 · 성공 프롬프트 요약 · AI 요약 · 과거 분석 결과
                       (진화 트리는 화면 더 구성되면 나중에 추가)
```

- **"프로젝트 목록 조회/선택" = 내 GitHub 레포 목록에서 선택**하는 것 (내부 생성 프로젝트 아님). 대시보드 = 깃허브 레포 목록(Vercel식 Import).
- **"프로젝트 삭제" = 레포 삭제 아님 → 동의(등록) 해제**(연동 취소). `DELETE /projects/{id}` soft-delete로 등록만 해제.
- 레포 선택 → 동의/액터 화면에서 작성해야 → 그때부터 스캔 가능.

## 3. 결정 반영 (2026-07-07 업데이트)

- **`ai 요약` (16) = 채택 확정.** LLM을 어느 정도 쓰는 게 낫고, **요약 기능이 LLM 쓰기 좋은 자리**라 리포트 AI 요약 유지. (기존 "AI요약 배제"에서 **변경**.) → LLM 사용 자리 = 변이·판정·정찰 + **리포트 요약** 추가. 리포트 요약 엔드포인트/필드 신설 필요(예: `GET /scans/{id}/report`에 `ai_summary` 또는 별도 `GET /scans/{id}/summary`).
- **진화 트리 = 후순위(나중).** 화면 더 구성되면 리포트에 추가. **지금 기능명세에 없는 건 문제 아님**(의도적 나중).
- **프로젝트 삭제 = 등록(동의) 해제.** 대시보드는 내 GitHub 레포 목록이라 **레포 자체 삭제 아님** → 동의한 대상 연동만 해제(`DELETE /projects/{id}` soft-delete). 별도 "레포 삭제" 기능 불필요.

## 4. 아직 검토할 것 (선택, 넣으면 좋음)

**분석페이지:** 공격 유형 선택(13종, `GET /attack-types`) · 분석 취소(`POST /scans/{id}/cancel`) · 타겟 모델 선택 — Analysis 화면에 추가 검토.
**리포트페이지:** 취약점 목록+완화책(`GET /scans/{id}/findings`) · 통계 숫자 4개(위험도/총시도/뚫림/취약점, `GET /scans/{id}/report`) — 넣으면 좋음. 진화 트리는 나중.

## 5. 결론
- **매칭 상태: 대부분 API에 매칭됨(✅ 11 / 🟡 4).** 화면 분류·핵심 흐름·플로우 모두 API 명세와 일치.
- **`ai 요약` = 채택 확정**(LLM 요약 도입). → API에 요약 필드/엔드포인트 추가 필요.
- **진화 트리·삭제**는 정리됨(진화트리=나중, 삭제=등록해제).
- 선택 추가 후보: 공격유형 선택·분석 취소·취약점목록+완화책·통계4개 (넣으면 완성도↑, 필수는 아님).
