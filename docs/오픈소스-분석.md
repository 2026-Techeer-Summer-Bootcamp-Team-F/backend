# AI 레드팀 — 오픈소스 아키텍처 분석 & 차용 설계

> 목표: 우리 도구(**"검증된 공격 seed를 벡터 코퍼스에서 retrieve → 유전 알고리즘식 evolve"**)를 만들기 위해
> 유사 OSS 5개를 실제 소스코드로 분석하고, **뭘 빌리고 뭘 버릴지** 확정.
> 검증: GitHub `main` 소스 + 논문 (2026-07). `기획.md §3` 보완.

| 변이 | `pyrit/prompt_converter/*` (**150+**) | 인코딩/번역/설득/media, **컨버터=오케스트레이터와 분리**(promptfoo는 결합) |
| 액터 | `pyrit/prompt_target/http_target/`, `playwright_target.py`, `round_robin_target.py` | `{PROMPT}` 템플릿+response callback, 브라우저 자동화, 엔드포인트 로테이션 |

**핵심 차용점: PyRIT의 파이프라인 분리** = `retrieve → convert → send → score → (loop)`. 각 단계 독립 모듈 = 우리가 그대로 따를 구조.

## 4. deepteam (Confident AI) — vulnerability↔attack 직교

- **`deepteam/vulnerabilities/`** (47개): bias/toxicity/pii_leakage/sql_injection/ssrf/bola/excessive_agency… = **무엇을 뚫나**
- **`deepteam/attacks/`**: **single_turn**(prompt_injection/roleplay/base64/leetspeak/rot13/multilingual…) + **multi_turn**(linear/tree/crescendo/bad_likert_judge) = **어떻게 전달**
- 2단 파이프라인(`attack_simulator.py`): ① vulnerability→baseline 목표 LLM 합성 → ② `random.choices()`로 기법 weight 샘플링 → `attack.enhance()`로 변환. **단 1회성 변환**(피드백 진화 아님, multi_turn 제외).
- **차용**: (a) vulnerability×attack 매트릭스 (b) `enhance()` template-method + weight 샘플링 (c) single/multi-turn 베이스 분리.

## 5. GPTFuzzer + AutoDAN — 우리 evolve 엔진의 실체 ★가장 중요

### 5.1 GPTFuzzer (USENIX Security 2024, `github.com/sherdencooper/GPTFuzz`)
소프트웨어 퍼징을 jailbreak 템플릿 진화에 적용. 부실 seed로도 90%+ ASR.

**메인 루프** (`gptfuzzer/fuzzer/core.py`):
```
1. select_policy.select()        # seed 하나 선택
2. mutate_policy.mutate_single() # LLM 변이
3. evaluate()                    # 모든 질문에 발사 → RoBERTa judge 성공/실패
4. update()                      # seed pool 반영 + reward 역전파
5. is_stop()
```
- **판정 = `hubert233/GPTFuzz` (finetuned RoBERTa-large)** — 빠르고 재현성 높은 black-box judge.
- **Seed 선택 (`selection.py`)**: Random/RoundRobin/**UCB**/**MCTS**(기본)/EXP3. UCB 점수 = `reward/(visited+1) + c·sqrt(2ln(step)/(visited+1))`. MCTS는 **깊이 페널티** `max(β, 1-0.1·level)`로 얕고 범용적 seed 선호. → **seed 선택 = multi-armed bandit 문제**.
- **변이 연산자 5종 (`mutator.py`, 전부 LLM 위임, placeholder 보존)**:
  | 연산자 | 동작 |
  |---|---|
  | `generate_similar` | 같은 스타일 새 템플릿 |
  | `crossover` | pool의 다른 템플릿과 교배 |
  | `expand` | 앞에 문장 3개 추가 |
  | `shorten` | 압축(의미 보존) |
  | `rephrase` | 재표현(의미 보존) |
- **Fitness** = seed의 jailbreak 성공률 `success_count/total_questions`.
- **종료**: `max_query`/`max_jailbreak`/`max_reject`/`max_iteration`.

### 5.2 AutoDAN (arXiv 2310.04451, Hierarchical GA)
자연스러운(stealth) jailbreak를 **계층적 유전 알고리즘**으로 진화 (GCG의 gibberish 문제 회피).
- **Fitness** = 타겟 응답 log-likelihood loss `-log P("Sure, here is..."|input)` (white-box, 로짓 필요).
- **Selection** = fitness softmax 룰렛 휠. **Elitism**: 상위 α는 무변형 생존 → 단조 개선 보장.
- **HGA 2계층**: 문단/문장(교차+LLM 변이) + 단어(**momentum word scoring**으로 중요단어 유의어 치환 → 지역최적 탈출).
- **종료**: max iteration or 거절키워드 없음(성공).

### 5.3 우리가 베낄 교훈
1. **명시적 population + seed pool 누적**(GPTFuzzer) — 우리 VERIFIED corpus가 초기 population.
2. **seed 선택을 UCB/MCTS bandit으로**(exploit↔explore + 깊이 페널티).
3. **변이 연산자 5종 그대로** + AutoDAN word-momentum 6번째 검토.
4. **Elitism**(AutoDAN) — 상위 seed 무변형 생존, 회귀 방지.
5. **Fitness 이원화**: black-box=RoBERTa 성공률(우리 기본), white-box 가능시 log-likelihood 추가.
6. **다층 변이**(문단/문장/단어)로 다양성.
7. **종료조건 세트**: max_query(비용)/max_jailbreak(성공)/max_iteration.

## 6. 우리 프로젝트 적용 — Evolve-Engine 설계

우리 파이프라인: **retrieve(벡터코퍼스) → seed → fire(타겟) → judge(fitness) → mutate → repeat**

### 6.1 각 도구 → 우리 컴포넌트 매핑
| 우리 컴포넌트 | 근거 도구 | 차용 요소 |
|---|---|---|
| **Retrieve (벡터 코퍼스)** | **(신규 차별점)** | 검증 seed semantic search로 초기 population 구성 |
| vulnerability/attack 분리 | deepteam | 직교 모듈 + 매트릭스 실행 |
| generator/judge/orchestrator 분리 | garak | probe/detector/harness 3분할 |
| 파이프라인 단계 분리 | PyRIT | retrieve→convert→send→score→loop 독립 모듈 |
| **Judge (fitness)** | GPTFuzzer + garak | `hubert233/GPTFuzz` RoBERTa + 거절탐지/LLM-judge 앙상블 |
| **Seed selection** | GPTFuzzer | UCB/MCTS bandit + 깊이 페널티 |
| **Mutation 연산자** | GPTFuzzer(+AutoDAN) | 5연산자 + word-momentum |
| **Elitism/단조개선** | AutoDAN | 상위 α 무변형 생존 |
| 액터(HTTP 템플릿+파서) | promptfoo + PyRIT | `{PROMPT}` 템플릿 + response 파서 |
| 밴회피 백오프 | promptfoo | 429+헤더+지터+하드쿼터 즉시실패 |
| ATLAS 정적 매핑 | promptfoo | 하드코딩 `{tactic→plugins}` 딕셔너리 (LLM 추론 금지) |
| 종료조건 | GPTFuzzer | max_query/jailbreak/iteration |
| multi-turn 확장 | deepteam/garak | crescendo/tree + atkgen 대화 루프 |

### 6.2 Evolve 루프 의사코드
```python
population = retrieve_verified_seeds(vulnerability, k)   # ★우리 차별점(벡터검색)
while not stop():                                        # GPTFuzzer is_stop()
    seed  = select_policy.select(population)             # UCB/MCTS (GPTFuzzer)
    child = mutate(seed, op ~ weighted[5_ops])           # 5연산자 (GPTFuzzer)
    resp  = fire(target, child, questions)               # 액터 (promptfoo/PyRIT)
    fit   = judge.fitness(resp)                          # RoBERTa 성공률 (GPTFuzzer)
    population.add_if_improved(child, fit)               # seed pool 누적
    select_policy.update(reward=fit)                     # reward 역전파
    elitism_keep_top(population, alpha)                  # AutoDAN elitism
    if fit.success: recollect_to_corpus(child)          # 성공변이→코퍼스 (복리효과)
```

### 6.3 "차용 vs 버림" 최종 판정 (promptfoo/PyRIT 상세)
| 패턴 | 판정 | 이유 |
|---|---|---|
| 적응 루프(attacker/target/judge) | **차용** | 우리 evolve가 곧 이 루프. PyRIT `while + backtrack` 골격 |
| LLM judge + threshold | **적응** | 루브릭을 우리 검증코퍼스 성공기준으로 시드 |
| 거절 시 backtrack | **적응** | "코퍼스서 형제 공격 재검색"으로 단순화 |
| 컨버터 = 오케스트레이터 분리 | **차용(PyRIT식)** | retrieve→transform→evolve에 적합 |
| 컨버터 150개 | **적응** | 인코더 + LLM재작성만, 훨씬 적게 |
| HTTP 액터(템플릿+파서) | **차용** | 우리가 필요한 타겟 커넥터 추상화 그대로 |
| 밴회피 백오프 | **차용(promptfoo식)** | 429+헤더+지터+하드쿼터, httpx로 포팅 |
| 엔드포인트 로테이션 | **버림** | 탐지회피=ToS 문제, 단일 인가 타겟 + 정직한 백오프 |
| 정적 ATLAS 테이블 | **차용(promptfoo식)** | 결정론적·감사가능·저렴, LLM 추론 금지 |
| seed 메타데이터(harm_category) | **차용** | 코퍼스 각 공격에 ATLAS 태그 → LLM 없이 롤업 |
| 브라우저 타겟(Playwright) | **적응** | API 없는 타겟만, 후순위 |
| 서버측 원격 생성 | **버림** | 호스팅 결합, FastAPI 로컬 생성 |

## 7. 핵심 요약 (발표용)

1. **우리 evolve 엔진 = GPTFuzzer 뼈대 + AutoDAN elitism/계층변이.** 학술 검증된(USENIX'24) 방법론.
2. **구조는 PyRIT/garak식 분리** — retrieve/convert/send/judge/orchestrate 독립 모듈.
3. **판정은 GPTFuzzer RoBERTa judge**(black-box·빠름·재현성) + 거절탐지 앙상블.
4. **차별점 = Retrieve** — 4개 도구는 정적 seed(CSV)/LLM 생성으로 시작하지만, **우리만 검증된 공격 코퍼스에서 벡터 검색으로 관련 seed를 뽑아 초기 population 구성** → 근거 있는 공격 + 수렴 가속.
5. **밴회피·ATLAS 매핑은 promptfoo 패턴 차용**(정적 테이블, 지터 백오프).
