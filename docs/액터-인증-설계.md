# 액터 인증(토큰 자동 발급/갱신) 설계

> 목적: `HttpActor`가 **로그인이 필요한 대상**에 공격을 쏘려면 토큰을 먼저 확보하고, 스캔 도중 만료되면 자동 갱신해야 한다.
> 현재 상태: 정적 토큰만 지원(`config.headers`에 박아둔 `Authorization`를 매 요청 그대로 전송, `actor.py:52`). 로그인 플로우·만료 갱신 **미구현**.
> 레퍼런스: promptfoo HTTP provider(OAuth `tokenUrl` 자동발급+만료 60초前 갱신, `sessionParser`, 파일기반 커스텀 토큰). 우리는 **선언적 config만**으로 제한(임의코드 실행 배제).

---

## 1. 지원할 인증 모드 (범위)

| type | 설명 | 우선순위 |
|---|---|---|
| `none` | 인증 없음 (현행 기본) | 있음 |
| `bearer` | 정적 토큰 1개 → `Authorization: Bearer {token}` (현행을 정식화) | 있음 |
| `api_key` | 헤더 또는 쿼리에 키 삽입 (`X-API-Key` 등) | 있음 |
| `oauth2_client` | client_credentials grant → `token_url`에서 자동 발급/갱신 | ★핵심 |
| `oauth2_password` | password grant (username/password) | ★핵심 |
| `login` | 범용: 임의 로그인 엔드포인트에 POST → 응답에서 토큰 추출(dot-path) | ★핵심 |

**배제(의도적):** 서명인증(HMAC/PEM), 파일기반 커스텀 코드(promptfoo `file://`) → 임의코드 실행/복잡도. 후순위·별건.

## 2. Config 스키마 (`target.config.auth`)

`target.config`는 자유 JSON이므로 하위에 `auth` 블록 추가. **비밀값은 값 자체 대신 환경변수 이름으로** 참조(§7 보안).

```jsonc
// oauth2_client
"auth": {
  "type": "oauth2_client",
  "token_url": "https://target/oauth/token",
  "client_id": "abc",
  "client_secret_env": "TARGET42_SECRET",   // ← 값이 아니라 env 변수명
  "scope": "chat",                            // optional
  "inject": {"in": "header", "name": "Authorization", "format": "Bearer {token}"}
}

// oauth2_password
"auth": {
  "type": "oauth2_password",
  "token_url": "...", "client_id": "...", "client_secret_env": "...",
  "username": "redteam-bot", "password_env": "TARGET42_PW", "scope": "..."
}

// login (범용)
"auth": {
  "type": "login",
  "login_url": "https://target/api/login",
  "method": "POST",
  "headers": {"Content-Type": "application/json"},
  "body_template": "{\"user\":\"bot\",\"pw\":\"{{password}}\"}",
  "password_env": "TARGET42_PW",
  "token_path": "data.accessToken",          // 응답 JSON dot-path
  "expires_in_path": "data.expiresIn",       // optional (초). 없으면 default_ttl
  "default_ttl": 900,                          // 초. expires 미제공 시 보수적 가정
  "inject": {"in": "header", "name": "Authorization", "format": "Bearer {token}"}
}
```

`inject.in` = `header` | `query` | `body`. 기본 header/Authorization/`Bearer {token}`.

## 3. 아키텍처 — `TokenProvider` 분리

새 파일 `app/engine/auth_provider.py`. 액터는 `provider.apply(headers, url, body)`만 부른다(엔진↔액터 분리 철학과 동일: 액터는 "어떻게 붙이는지" 몰라도 됨).

```python
# auth_provider.py (3.9 호환)
import asyncio, os, time, json
from dataclasses import dataclass
from typing import Optional
import httpx

@dataclass
class TokenState:
    value: str
    expires_at: float   # epoch seconds (절대시각)

class TokenProvider:
    """type별 구현체가 _fetch()만 채운다. 캐시·갱신·동시성은 공통."""
    REFRESH_BUFFER = 60  # 만료 60초 전 갱신 (promptfoo 동일)

    def __init__(self, cfg: dict, cache_key: str):
        self.cfg = cfg
        self.cache_key = cache_key      # (target_id, auth지문) → 액터 재생성해도 공유
        self._inject = cfg.get("inject", {"in": "header",
            "name": "Authorization", "format": "Bearer {token}"})

    async def token(self) -> str:
        st = _CACHE.get(self.cache_key)
        if st and time.time() < st.expires_at - self.REFRESH_BUFFER:
            return st.value
        async with _lock_for(self.cache_key):          # thundering herd 방지
            st = _CACHE.get(self.cache_key)             # double-check (락 안에서 재확인)
            if st and time.time() < st.expires_at - self.REFRESH_BUFFER:
                return st.value
            st = await self._fetch()
            _CACHE[self.cache_key] = st
            return st.value

    async def invalidate(self):                         # 401 강제 갱신용
        _CACHE.pop(self.cache_key, None)

    async def apply(self, headers: dict) -> dict:       # 요청 직전 주입
        tok = await self.token()
        inj = self._inject
        if inj["in"] == "header":
            headers = dict(headers)
            headers[inj["name"]] = inj["format"].replace("{token}", tok)
        return headers                                  # query/body 주입은 send에서 처리

    async def _fetch(self) -> TokenState:               # 구현체가 오버라이드
        raise NotImplementedError

# 모듈 전역 캐시 + 키별 락
_CACHE: dict = {}
_LOCKS: dict = {}
def _lock_for(key): return _LOCKS.setdefault(key, asyncio.Lock())

def _secret(cfg: dict, val_key: str, env_key: str) -> str:
    if cfg.get(env_key):        # env 참조 우선
        return os.environ.get(cfg[env_key], "")
    return cfg.get(val_key, "") # 하위호환(값 직접) — 경고 대상
```

**구현체 예 (oauth2_client):**
```python
class OAuth2ClientProvider(TokenProvider):
    async def _fetch(self) -> TokenState:
        data = {"grant_type": "client_credentials",
                "client_id": self.cfg["client_id"],
                "client_secret": _secret(self.cfg, "client_secret", "client_secret_env")}
        if self.cfg.get("scope"): data["scope"] = self.cfg["scope"]
        js = await _post_with_backoff(self.cfg["token_url"], data=data)  # 밴회피 재사용
        return TokenState(js["access_token"],
                          time.time() + float(js.get("expires_in", 3600)))
```

`login`은 `body_template`에 `{{password}}` 치환 후 POST, `token_path`/`expires_in_path`를 dot-path로 추출. `default_ttl` fallback.

**팩토리:** `make_provider(target.config.auth, cache_key)` → type 분기 (actor.py의 `make_actor`와 대칭).

## 4. `HttpActor` 통합 지점 (actor.py 수정)

핵심 변경 3곳:

1. `__init__`: `self.auth = make_provider(config.get("auth"), cache_key=f"{target_id}:{fingerprint}")` (auth 없으면 None).
2. `send()`: **요청 직전** 헤더를 매번 재조립 — `headers = await self.auth.apply(self.headers)` (토큰이 갱신되면 반영). auth=None이면 기존 그대로.
3. **401/403 특수처리(중요):** 현재 코드는 `resp.raise_for_status()`(`actor.py:61`)가 401에서 예외 → generic 네트워크 재시도로 빠져 **스테일 토큰으로 헛재시도** 후 실패. → `raise_for_status` **이전에** 401/403을 가로채:
   ```python
   if resp.status_code in (401, 403) and self.auth and not self._reauthed:
       await self.auth.invalidate()
       self._reauthed = True         # 1회만 강제 재인증
       continue                       # 새 토큰으로 재발사
   ```
   재인증 후에도 401이면 → `[ACTOR_ERROR] auth_denied` 반환(무한루프 금지).

토큰 발급 요청 자체의 429/5xx는 **기존 밴회피 백오프를 공용 함수 `_request_with_backoff`로 추출**해 재사용(actor.py의 send 로직 = provider의 `_post_with_backoff`).

## 5. 프리플라이트(스캔 전 1회 인증 확인) — evolve.py 수정

문제: 토큰 발급이 실패하면 모든 세대의 모든 시도가 `[ACTOR_ERROR]`(score 0)로 낭비되고, 리포트엔 "안 뚫림"으로 오인됨.
대응: `run_scan`의 objectives 루프 **직전**에 1회 `await actor.auth.token()` 시도:
- 성공 → 진행(토큰 캐시에 예열됨)
- 실패 → `scan.status="failed"`, 명확한 사유 `auth_failed: {상세}` 이벤트 발행 후 종료. (지금은 `except`가 에러타입만 남김 → 사유 구체화)

## 7. 오류·엣지케이스 분석 ★

| # | 문제 | 발생 상황 | 대응 |
|---|---|---|---|
| 1 | **토큰 발급 실패 → 스캔 전체 낭비** | token_url 다운/오설정 | §5 프리플라이트로 조기 실패 + 사유 명시 |

| 11 | **토큰 위치가 헤더가 아님** | 쿼리/바디에 토큰 요구 | `inject.in = header\|query\|body` 지원 |
| 12 | **token_path 오설정 → 토큰 없음** | 응답 구조 불일치 | 추출 실패 시 `[ACTOR_ERROR] token_not_found: {path}` 명확 반환 |
| 13 | **메모리 캐시에 비밀/토큰 잔존** | 스캔 종료 후 | 스캔 종료 시 해당 키 `_CACHE`/`_LOCKS` 정리(cleanup). 프로세스 메모리 한정(PoC 허용) |

## 8. 시퀀스 (oauth2_client, 만료 갱신 포함)

```
run_scan
  └ 프리플라이트: provider.token() → 캐시 없음 → _fetch(token_url) → TokenState 캐시
  └ for objective: make_actor (provider 캐시 공유)
       └ send(prompt):
            headers = provider.apply(base)   # 캐시 유효 → 그 토큰
            POST target
            ├ 200 → judge
            ├ 401 & !reauthed → provider.invalidate() → continue(재발급→재발사)
            └ 429/5xx → 백오프 재시도
       ...만료 시점 도달...
       └ send: provider.token() → now≥expires-60 → 락 획득 → _fetch(재발급) → 새 토큰
```

## 9. 테스트 계획 (`tests/test_auth_provider.py`)

httpx `MockTransport` 또는 로컬 스텁(`/dummy/auth/token`)으로:

9. **token_path 오설정** — `token_not_found`.

## 10. 결정 확정 (A · B · C)

### A. 비밀 저장 = **env 변수 참조 표준** (DB에 비밀 안 남김)

**결정:** client_secret/password는 `target.config`에 **절대 값으로 안 넣고**, env 변수 *이름*만 넣는다(`client_secret_env`, `password_env`). 실제 값은 프로세스 환경변수(shell export / docker-compose `environment` / `.env`)에 둔다.

**왜:** `target.config`는 DB(JSON)에 평문 저장 → DB 덤프 시 비밀 유출. env 참조면 **DB엔 이름만**, 값은 프로세스 메모리에만. 12-factor 표준.

**구현 단위:**
```python
# auth_provider.py — env 우선, 값 직접입력은 하위호환+경고
import logging; log = logging.getLogger("redteam.auth")

def _secret(cfg: dict, val_key: str, env_key: str) -> str:
    if cfg.get(env_key):
        v = os.environ.get(cfg[env_key], "")
        if not v:
            raise AuthConfigError(f"env {cfg[env_key]} 미설정")  # 프리플라이트서 조기 실패
        return v
    if cfg.get(val_key):
        log.warning("auth 비밀을 config에 평문 저장 중 — %s_env 사용 권장", val_key)
        return cfg[val_key]          # 하위호환(비권장)
    raise AuthConfigError(f"{val_key} 또는 {env_key} 필요")
```
- **주의(설정 로딩):** 임의 env 이름(`TARGET42_SECRET`)은 `config.py`의 pydantic `Settings`(선언 필드만 로딩)로 안 들어온다 → **`os.environ` 직접 조회**. `.env`에 넣고 쓰려면 프로세스에 로딩돼 있어야 함(docker-compose는 `env_file`로 자동, 로컬은 `export` 또는 `python-dotenv`). 문서에 명시.
- **로그 마스킹:** 토큰/비밀은 로그·`judge_detail`·SSE payload에 **절대 안 실음**(payload엔 프롬프트·verdict만, `evolve.py:151`). 스캔 이벤트에 헤더 안 남김.
- **Prod 확장(후순위):** DB에 넣어야 할 이유가 생기면 `users.access_token_enc`와 동일하게 Fernet 암호화 컬럼(`crypto.py` 헬퍼) 추가. **표준은 어디까지나 env.**
- **DB 스키마 영향 = 없음.** (아래 B의 핵심)

### B. 순서 = **auth는 ERD리팩터·벡터검색 다음**, 단 지금 설계 확정 (직교라 충돌 0)

**핵심 발견:** env 참조(A) + 메모리 토큰캐시(§3) 채택으로 **auth는 새 DB 컬럼이 0개**다. auth 설정은 이미 있는 `target.config`(JSON) 안에 얹힐 뿐. 따라서 **ERD 리팩터(`targets`→`target_projects`)와 완전히 직교** — 리팩터가 auth를 신경 쓸 필요 없고, auth가 리팩터를 기다릴 필요도 없다.

**결정 순서 (NEXT.md 반영):**
1. **ERD 모델 리팩터** (models 10테이블 정합) — auth와 무관하게 진행
2. **벡터검색 채우기** (최대 차별점)
3. **액터 auth** (이 문서) — 위 둘과 독립, 데모 불필요한 "실사용 대비"라 마지막

S1은 **리팩터라 위험 0**(외부 동작 동일), 발표 전에 미리 넣어도 안전. S2~S4는 발표 후.

### C. 특이 인증(HMAC 서명 등) = **확장 seam만 남기고 MVP 배제**

**결정:** 서명(HMAC/PEM)·파일기반 커스텀 코드는 **지금 구현 안 함**. 대신 나중에 **새 `TokenProvider` 서브클래스 추가만으로** 되도록 확장점을 열어둔다(코어 수정 불필요).

**확장 seam 설계:**
- `TokenProvider.apply(headers)`가 **주입 지점을 이미 추상화**(header/query/body) → 서명값도 여기로 주입.
- 미래 `type: "hmac"` → `HmacProvider(TokenProvider)`가 `_fetch` 대신 `apply`를 오버라이드해 요청별로 `HMAC-SHA256(canonical_request, secret_env)` 계산 후 `X-Signature`/`X-Timestamp` 주입.
- `make_provider`의 type 분기에 한 줄 추가하면 끝. **코어(캐시/락/액터)는 안 건드림.**
- 왜 배제: HMAC은 요청 바디별로 서명을 다시 계산해야 해(캐시 불가) 캐시 모델과 성격이 다르고, 인가 타겟에서 흔치 않음 → 수요 생기면 그때.

**요약:** A=env참조(DB비밀0), B=순서는 3번째지만 설계 확정·DB충돌0·PR 4단계, C=코어 안 건드리는 확장 seam만.
