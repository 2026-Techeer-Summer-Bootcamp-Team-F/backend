# 정찰 확장 — 레포/네트워크에서 액터 config 자동 구성 (설계 노트)

> 목적: 사용자가 액터 정보(url/body/response_path/시스템프롬프트 등)를 **몰라도/입력 안 해도**, 레포 코드나 네트워크에서 자동 추출해 액터를 구성한다.
> 상태: **미구현(아이디어).** 현재 `recon.py`는 레포 분석이 stub(`recon.py:24`), 액터 config는 사용자 수동 입력만.
> 근거: 기획 §5.1.2(화이트박스 정찰), §5.6(액터). 이 문서 = 그 확장 설계.

---

## 1. 액터 config를 얻는 3가지 소스

| 방법 | 필요한 것 | 장점 | 상태 |
|---|---|---|---|
| ① 사용자 수동 입력 | 사람이 앎 | 단순 | ✅ 구현됨 |
| ② 네트워크 캡처 | 실행 중 앱 + (로그인) | 실행 중이면 확실 | ❌ 미구현 |
| ③ **레포 코드 분석** | 레포만 | 실행·인증 불필요, 정찰과 한 번에 | ❌ 미구현(이 문서) |

**핵심:** ③이 가장 강함 — 앱을 실행하거나 로그인하지 않아도 **코드만 읽어** 액터 config + 정찰정보(시스템프롬프트/방어/모델)를 한 번에 뽑는다.

---

## 2. 레포 코드에서 뽑는 것 (무엇을 → 어디서)

### (a) 프론트 코드 → 액터 config
프론트의 API 호출부(fetch/axios)에 액터 config가 그대로 있음:
```js
fetch('/api/chat', { method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({ message: userInput }) })     // → body_template {"message":"{{prompt}}"}
  .then(r=>r.json()).then(d=> setReply(d.reply))       // → response_path "reply"
```
추출: `url`(경로), `method`, `headers`, `body_template`, `response_path`.

### (b) 백엔드 라우트 → 엔드포인트·스키마
라우트 핸들러(FastAPI/Express 등)에서 엔드포인트 경로 + 요청/응답 스키마 확인 (프론트 추출 교차검증).

### (c) 정찰 5종 (기획 §5.1.2, 기존 항목)
`model`(모델ID) / `system_prompt`(하드코딩 프롬프트) / `defenses`(llm-guard·moderation) / `tools`(함수정의) / `rag_sources`(RAG 문서).
- **시스템프롬프트를 코드에서 얻으면 → 유출 판정이 카나리 없이 정확해짐** (기획 §5.1).

## 3. 구현 방식

- **`기획/poc/static_scan/` AST 스캐너 재활용** — 이미 AST 기반 코드 스캐너 있음(`기획/poc/static_scan/code_scan/ast_scanner.py`). 이걸 확장해 위 패턴 추출.
- 프론트: JS/TS 파싱(fetch/axios 호출 노드) — grep 1차 + AST 2차. (JS 파싱은 백엔드보다 지저분 → 정규식 폴백)
- 백엔드: 라우트 데코레이터/핸들러 파싱(Python은 AST 깔끔).
- GitHub 접근: `users.access_token_enc` 토큰으로 레포 clone/API. (`repo` OAuth 스코프 필요 — 비공개·코드 읽기)
- 산출: `target_projects`의 `config`(액터) + `model/defenses/tools/rag_sources/system_prompt` 자동 채움 → 사용자는 확인·수정만.

---

## 4. 주의·한계

1. **실제 공격은 여전히 "실행 중 base URL"에 쏨.** 코드는 경로/형식(`/api/chat`, body)을 주지만, 공격하려면 배포된 `https://앱.com/api/chat`이 있어야. → 코드=형식, 공격=실행 인스턴스. base URL은 사용자 입력 or 배포정보에서.
2. **토큰은 코드에 보통 없음**(런타임 env). 인증 토큰은 사용자 입력 or 로그인으로. (→ `액터-인증-설계.md`)
3. **JS/프론트 파싱 지저분** — 동적 라우팅·env·번들링으로 못 뽑는 경우 → 네트워크 캡처(②)나 수동 입력(①)로 폴백.
4. **커밋 히스토리 시크릿**(옛 커밋의 지운 키/프롬프트)은 별개 확장 각도 — 여기 범위 아님.

---

## 5. 폴백 체인 (권장 UX)
```
③ 레포 코드 분석 (레포 있으면 자동 추출)
   └ 실패/레포 없음 → ② 네트워크 캡처 (실행 중 앱을 Playwright로 열어 요청 인터셉트)
        └ 실패 → ① 사용자 수동 입력 (url/body/response_path 또는 browser selector)
```
어느 단계든 결과는 사람이 **확인·수정** 후 확정(자동감지 불안정 대비, 기획 §5.6 정신).
