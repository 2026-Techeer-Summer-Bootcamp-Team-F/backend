# 진화 엔진 정리 — 출처·파이프라인·AI 사용처·차별점

> 목적: 진화 파이프라인이 **어디서 왔고, 어떤 순서로 돌고, AI(LLM)는 어디에 얼마나 쓰이고, 무엇이 우리 신규인지**를 한 곳에 정리. (2026-07-07 논의 기준)
> 근거: `기획.md §2·§4·§5`, `오픈소스-분석.md §5·§6`, 실제 코드 `app/backend/app/engine/*`.

## 1. 진화 코드는 어디서 왔나

| 요소 | 출처 | 우리 코드 |
|---|---|---|
| 진화 루프 뼈대 (select→mutate→fire→judge→update→stop) | **GPTFuzzer** (USENIX Security 2024, `sherdencooper/GPTFuzz`) | `evolve.py:134` `_evolve_objective` |
| 씨앗 선택 = **UCB bandit** | GPTFuzzer `selection.py` → 원조 **UCB1**(Auer 2002), **UCT/MCTS**(Kocsis-Szepesvári 2006) | `evolve.py:38` `_ucb` |
| **Elitism**(상위 α 무변형 생존) | **AutoDAN** (arXiv 2310.04451, 계층적 GA) | `evolve.py:222-226` (α=4) |
| 5 변이 연산자 | GPTFuzzer `mutator.py` | `mutators.py:26` |
| 성공→풀 재투입(in-run) | 소프트웨어 퍼징 **AFL/libFuzzer** → GPTFuzzer seed pool | `evolve.py:222` (메모리 한정) |

**핵심:** 알고리즘 골격은 빌려온 게 맞고 정상(= sqlmap도 기법 발명이 아니라 자동화+DB). 단 우리는 GPTFuzzer 코드를 그대로 안 쓰고 **우리 스택에 ~150줄로 재구현**했고, **GPTFuzzer는 변이가 전부 LLM인데 우리는 결정론 우선 + LLM 옵션으로 뒤집음.**

## 2. 파이프라인 순서 (정찰부터 대시보드까지)

```
① 정찰(Recon)         대상 프로파일 {model,purpose,defenses,tools}     recon.py / evolve.py:94
② 필터=씨앗검색       검증 코퍼스에서 관련 씨앗 K개 (verified 우선)      corpus.py:89 search_seeds
③ 0세대 발사          씨앗 K개 그대로 발사 → population 초기화            evolve.py:182  [LLM 0]
④ 발사(Actor)         HTTP/브라우저로 대상에 쏨                          actor.py
⑤ 판정(Judge)         0.0~1.0 fitness (거절0.1 / 참여0.3~0.85 / FLAG1.0)  judge.py   ★진화의 나침반
⑥ 진화 세대 루프      선택(UCB)→변이→발사→판정→역전파→도태(elitism)      evolve.py:198~  ★발전 지점
⑦ 종료(5중1)          성공/예산/정체/전멸/시간                            evolve.py:218,236
⑧ ATLAS 매핑          정적 테이블로 기법ID 라벨 (LLM 추론 없음)           atlas.py
⑨ 대시보드            진화트리(parent_attempt_id)+히트맵+증거+완화책      evolve.py:143
```

**"발전(진화)"이 일어나는 곳 = ⑥.** 씨앗(0세대)이 못 뚫으면 → 프레이밍 추가(1세대) → base64 난독화(2세대) → 롤플레이 결합(3세대) … 세대마다 fitness 신호를 따라 개선돼 임계값을 넘김. `run_demo.py`가 실제로 이렇게 FLAG를 뚫음.

## 3. AI(LLM)는 어디에 쓰이나 — 기획상 딱 3자리, 최소화

기획 대전제(§4·§6) = **"LLM을 최대한 안 부른다."** promptfoo/PAIR는 매 루프 공격자LLM+판정LLM을 부르지만, 우리는 그걸 **DB검색+룰로 대체**한 게 차별점(기획 §2 "발명형이 아니라 검색+진화형").

| 자리 | 기획 | 현재 코드 |
|---|---|---|
| **① 변이 — 창의적 변형** | DB검색(L0)·코드변형(L1)로 대부분 커버, 소진 시 **로컬 모델(L2) 우선 / 상용(L3) 최후** | ❌ 결정론 6연산자만 (`mutators.py`) |
| **② 판정 — 애매한 극소수** | 룰·라이브러리로 안 갈리면 Haiku 1회 | ❌ 룰+카나리+휴리스틱만 (`judge.py`) |
| **③ 정찰 — 리포 요약** | grep+AST+**LLM요약**으로 공격표면 추출 | ❌ 자리표시 (`recon.py:24`) |
| (별개) 씨앗 검색 임베딩 | ingestion 때 1회 임베딩 → pgvector 랭킹 | ❌ 카테고리 필터만 (`corpus.py:97`) |

**나머지(선택·발사·ATLAS·1세대) = LLM 0. 대상 앱만 당연히 AI(공격 대상).**

→ **현 상태: 위 자리 전부 미배선.** 지금 백엔드는 **AI 0으로 FLAG를 뚫음**(밴 원천 차단). LLM은 "없으면 안 되는 핵심"이 아니라 **"얹으면 품질↑" 옵션.**

## 4. 밴 문제 — "해결"의 정도

상용 LLM에 "공격 프롬프트 만들어줘" 반복 = 거부/계정 밴 위험(기획 §5.3.1, 실제 경험).

**실제로 만들어진 것 = `poc2_generate_attack.py` (PoC 데모, 엔진과 별개):**
- **LIVE 모드**: Claude API 호출 + `"authorized red-team"` 프레이밍(`poc2:59`) = L3. 거부를 줄이지만 **밴 무효화는 아님**.
- **DEMO 모드**: 사전생성 출력 재생(`poc2:37`), API 안 부름. 발표 슬라이드가 이것.

**아직 안 된 것 = 진짜 "밴 걱정 0" 방법:** 기획의 **L2 = 로컬 uncensored 모델(Ollama)에 위험 생성 격리.** 미구현 + 엔진 미연결. → 그래서 지금은 그냥 LLM을 안 부르는 것으로 회피 중.

## 5. 빌려온 것 vs 우리 신규 (차별점)

| | GPTFuzzer/AFL/promptfoo | 우리 |
|---|---|---|
| GA/UCB/elitism 루프 | ✅ | 재구현(빌림) |
| **검증 코퍼스 + 벡터검색을 유전자 풀로** | ❌ (씨앗 몇 개로 시작) | ⭐ 신규 |
| **정찰 → 필터** (라이브 앱 자동 프로파일링) | ❌ | ⭐ 신규 |
| **실제 배포 앱 공격** (HTTP/브라우저/인증 액터) | ❌ (모델 API만) | ⭐ 신규 |
| **ATLAS 매핑 + 진화트리 + 리포트** (제품층) | ❌ (연구 스크립트) | ⭐ 신규 |

**우리 핵심 = "검증 코퍼스에서 검색→진화→라이브 앱 자동 발사→ATLAS 리포트" (= AI판 sqlmap).** LLM은 그 위 정밀도 옵션이지 본질이 아님.

## 6. 자기학습 코퍼스 (복리 효과) — recollect_to_corpus

`오픈소스-분석.md §6.2` 의사코드: `if fit.success: recollect_to_corpus(child)` — **성공한 변이를 코퍼스에 되먹임.**

**출처 구분:**
- "성공→풀 재투입" 개념 = **AFL 퍼징 / GPTFuzzer에 있음.** 단 **한 run 안, 메모리 한정.** 세션 끝나면 버림.
- **"세션 넘어 영구 코퍼스에 verified로 쌓여, 다음 스캔이 벡터검색으로 재사용(복리)"** = **오픈소스엔 없음. 우리 영속DB+pgvector라야 성립하는 확장.** → "쓸수록 세지는 도구" 서사 = 강한 차별점.

**현재: 미구현.** 지금은 성공 시 `Finding`만 기록, 성공 프롬프트를 새 씨앗으로 `attack_cases`에 안 넣음.

**구현 스케치(5~10줄, evolve.py `_record_finding` 부근):**
```python
db.add(AttackCase(
    prompt_text=at.prompt_text, attack_type=category,
    atlas_technique_id=obj.atlas_technique_id,
    source="evolved", verified=True,
    worked_on=[target.model_hint] if target.model_hint else [],
    tags=["evolved", op], embedding=None))   # embedding은 벡터검색 붙일 때 생성
```

## 7. 후보 작업 (미구현, 우선순위 참고)

1. **벡터검색** (`attack_cases.embedding` 생성 + 코사인) — 씨앗 관련성↑, 최대 차별점 (NEXT.md B)
2. **자기학습 코퍼스** (§6 recollect_to_corpus) — "복리" 서사, 벡터검색과 짝
3. **로컬 모델 변이(L2)** — 밴 없는 창의적 진화 (Ollama)
4. **LLM 판정(③)** — 애매한 응답만 정밀 채점
5. **정찰 리포 요약** — 화이트박스 공격표면 추출
