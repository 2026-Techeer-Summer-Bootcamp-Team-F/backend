# AI 앱 자동 모의해킹 (AI Red Teaming) 도구 — 통합 기획서

> AI 챗봇·에이전트 앱을 대상으로, **실전 검증된 공격 사례 DB**를 씨앗으로 삼아
> AI가 스스로 공격을 진화시켜 "이 앱이 프롬프트 공격에 뚫리는지"를 진단·시각화하는 도구.

- 문서 상태: **현행 단일 기준 문서** (이전 기획들은 `_archive/`로 이관, 아래 §0 참고)
- 최종 정리: 2026-07-03

## 0. 이전 방향과의 관계 (중요)

이 프로젝트는 원래 **"통합 보안 분석 플랫폼"**(정적 스캔 Semgrep/Trivy + 실시간 로그 +
Correlation Engine + CVSS/EPSS/KEV 스코어링)이었으나 → **"AI 앱 자동 레드티밍"**으로 완전 전환됨.

## 1. 정의 & 대상

**한 줄 정의**: 자기 AI 앱을 등록하면, 도구가 실전 공격 DB로 정찰→맞춤공격→진화하며
자동 침투 테스트를 수행하고, MITRE ATLAS 기준으로 "어디가 뚫렸는지"를 리포트한다.

**대상 사용자**
- AI 챗봇·에이전트 앱을 만들거나 운영하는 개발자·팀
- 보안 검증은 필요한데 전담 인력이 없어 자동 점검이 필요한 팀

**핵심 전제**: 남의 앱이 아니라 **자기 앱을 스스로 점검**한다 (self-testing). 이 전제가
액터 방식·정찰·인가 설계를 전부 좌우한다.

## 2. 핵심 차별점 — "발명형"이 아니라 "검색+진화형"

| | 일반 도구 (promptfoo/PAIR) | **우리** |
|---|---|---|
| 공격 생성 | 공격자 LLM이 맨땅에서 발명 | **검증된 공격 DB에서 검색 → 진화** |
| 근거 | 없음 (상상) | "이건 실제로 GPT-4o를 뚫은 프롬프트" |
| ATLAS 매핑 | 사후 추론(불안정) | DB에 **미리 라벨**(authoring-time) |
| 비용 | iteration 많음 | 검증 씨앗에서 출발 → 적은 iteration |

**학계 선례**: GPTFuzzer, AutoDAN — "실제 jailbreak 씨앗 + 변이 + 판정 기반 진화 = 유전 알고리즘".
우리 도구 = **공격 프롬프트의 유전 알고리즘**, 유전자 풀 = 실전 공격 DB.

## 3. 경쟁/참고 도구 실제 구현 분석 (GitHub 코드 기준)

> 아래는 실제 저장소 코드를 읽고 정리한 것. "이미 있는 것"과 "우리가 만들 것"의 경계를 명확히.

### 3.1 promptfoo — 우리가 만들려는 것의 레퍼런스 구현

- **적응형 공격 = PAIR 방식** (`src/redteam/providers/iterative.ts`, 929줄).
  LLM을 **3역할**로 분리: 공격자(Attacker) → 대상(Target) → 판정(Judge). 논문 arxiv 2312.02119.
  ```
  for i in range(numIterations):
      공격자LLM(점수·이유 피드백 보고 프롬프트 개선)  # {improvement, prompt} JSON
      → 대상앱(getTargetResponse)
      → 판정LLM(1~10점 채점)
      if graderPassed == False: break   # 성공 시 종료
  ```
- **종료 조건** (실제 코드): `StopReason = 'Grader failed' | 'Max iterations reached'` — 딱 2개.
  → 우리가 잡은 "성공 / 예산" 종료 조건과 동일.
- **흥미로운 설계**: 공격자는 대상의 *실제 응답을 안 봄*. 오직 점수+이유만 피드백받음
  (강화학습 보상 신호처럼). `improvement` 필드 = "AI 추론 과정" → 대시보드에 그대로 노출 가능.
- **개념 3분할** (그대로 차용 권장):
  - `plugins/` = **무엇을 공격하나** (pii, indirect-prompt-injection, dataExfil, hijacking … 13종 대부분 이미 존재)
  - `strategies/` = **어떻게 전달하나** (crescendo, iterative, base64, leetspeak, multilingual …)
  - `providers/` = **액터** (대상 연결)
- **액터 = 코드가 아니라 설정** (`src/providers/http.ts`, 3266줄이지만 핵심 5개 필드).
  나머지는 전부 인증(OAuth/인증서/서명). 유저는 `url/method/headers/body/transformResponse`만 채움.
  브라우저 액터(`browser.ts`)는 `steps`(navigate→type→click→extract) = Playwright.
- **밴 회피** (`src/util/fetch/index.ts`): 429/`x-ratelimit-remaining=0` 감지 → 서버의
  `Retry-After`/`X-RateLimit-Reset` 헤더 읽어 **정확한 시간 대기 + 랜덤 지터**(retry storm 방지)
  → 502/503/504는 지수 백오프(1→2→4초) → `maxRetries` 초과 시 포기.
- **ATLAS/OWASP 매핑 = 정적 룩업 테이블** (`src/redteam/constants/frameworks.ts`).
  `OWASP_LLM_TOP_10_MAPPING`, `MITRE_ATLAS_MAPPING`이 **카테고리 → plugins** 를 하드코딩.
  **LLM으로 사후 추론하지 않음.** → 우리도 정적 매핑 테이블로 가야 한다는 강력한 근거.

### 3.2 나머지

- **PyRIT** (MS): 파이썬 **라이브러리**(API 아님, `pip install`). 멀티턴 적응형 오케스트레이터 +
  **Scorer**(성공 판정). `SelfAskScaleScorer`(1~N점) = 우리 fitness와 동일. → **판정 프롬프트 참고용**.
- **garak** (NVIDIA): probe 기반 **정적** 스캐너, JSONL 출력, detector로 판정. → 무차별식, 적응 없음.
- **AgentDojo** (ETH): **고정 벤치마크**(연구용). 시뮬레이션 환경에 모델 꽂아 점수화.
  → 공격 설계·판정 로직 참고용. 그대로 따라가면 우리 차별점(적응+라이브 앱) 소멸.
- **llm-guard** (protectai): 방어(가드레일)용 output scanner (Toxicity/Sensitive/NoRefusal).
  → **우리는 이걸 "판정기"로 역이용** (§5.5).

**결론**: promptfoo/PyRIT는 "정답지"로 참고하되 **통째로 끌어오면 무겁다.** 핵심 루프(PAIR)는
100~150줄이면 직접 구현 가능. 차별화(DB진화·리포정찰·ATLAS·대시보드)에 자원 집중.

## 4. 전체 파이프라인

```
[대상 등록]
    │
① 정찰(Recon) ─ 등록입력 / 리포분석 / 블랙박스 프로빙 (§5.1)
    │  └→ 프로파일: {model, purpose, defenses, tools}
    ▼
② 필터 ─ 프로파일을 DB 조회 조건으로 (60만 → 수십 개로 좁힘)
    │
③ 1세대(정적) ─ 좁혀진 DB에서 씨앗 K개 그대로 발사  [LLM 안 씀 = 쌈]
    │  └→ 판정(§5.5)으로 fitness 채점
    ▼
④ 진화(2세대~) ─ 선택(도태) + 변이
    │  ├─ 싼 경로: DB에서 같은 계열 다른 검증 공격 꺼냄  [LLM 0원]
    │  └─ 비싼 경로: DB 소진 시 LLM이 few-shot으로 창의적 변이
    │  └→ 종료 조건(§5.4) 만족까지 반복
    ▼
⑤ ATLAS 매핑 ─ 정적 테이블로 결과에 기법ID 부여 (§5.7)
    ▼
⑥ 대시보드 ─ ATLAS 히트맵 + 진화 트리 + 증거 + 완화책
```

핵심 사상: **DB를 "참고자료"가 아니라 "LLM 호출을 줄여주는 값싼 변이 소스 + 근거 제공자"로 사용.**

## 5. 상세 설계

### 5.1 정찰 (Recon) — 3단계, 정확도 순

**등록 시 인가 확인 (필수)**: 대상 앱이 **본인 소유/권한임을 확인하는 단계**를 둔다.
리포 주소 제공(=코드 열람 권한)과 그 엔드포인트를 공격할 권한은 별개이므로, 도메인 소유 확인
또는 조직 내 등록으로 대상 소유를 검증한 뒤에만 스캔을 허용한다. PoC는 자체 더미 앱만.

자기 앱이라는 전제 덕분에 대부분 "추측"이 아니라 "확인"이 된다.

1. **등록 시 입력** (제일 정확·공짜): 유저가 아는 것 직접 — 모델, 용도, 시스템 프롬프트(알면).
2. **리포 분석** (화이트박스) ★ 원래 정적스캔 경험 재활용:
   - 유저가 GitHub 리포 제공(선택) → 코드에서 **모델ID / 시스템프롬프트 / 방어(llm-guard·moderation)
     / 도구·함수정의 / RAG소스** 5가지만 grep+AST+LLM요약으로 추출.
   - 시스템 프롬프트를 코드에서 얻으면 유출 성공 판정이 정확해짐(카나리 불필요).
   - **전체 코드 감사는 하지 않음** — 공격 표면 매핑만.
3. **블랙박스 프로빙** (폴백): 위 둘로 모르는 것만 5~10개 프롬프트로 찔러 파악
   — 모델 지문 / 용도 / **방어 탐지**(뭐가 막히나) / 도구 유무.

정찰 결과 → 그대로 DB 필터 조건: `WHERE model IN worked_on AND attack_type IN (...) AND verified=true`.

### 5.2 공격 데이터베이스 (씨앗 코퍼스) + 검색

- 통합 대상 데이터셋: jailbreak_llms(DAN/In-The-Wild), HackAPrompt, L1B3RT4S(Pliny), SPML.
- 통합 스키마 → §8.
- **검색은 순수 RAG 아님, 하이브리드**:
  1. 메타데이터 필터(SQL, 거의 공짜) → 60만 → 수백
  2. 그 수백 개만 벡터 랭킹(pgvector) → 빠름
- 효율화: ①임베딩은 ingestion 때 1회만 ②중복 클러스터링(60만→대표 수천)
  ③**성공 가중치**(실제 먹힌 씨앗 우선순위↑ = DB가 학습, bandit).

### 5.3 진화 엔진 (심장)

```
1. 필터된 DB에서 씨앗 K개 → population 초기화
2. 각 씨앗 발사 → 판정기가 fitness 점수
3. 선택: 점수 높은 것 생존, 낮은 것 도태
4. 변이:
   - 우선 DB 검색으로 유사 검증 공격 꺼냄  (LLM 안 씀)
   - DB 소진 시 LLM + few-shot(검색된 성공사례 예시 주입)로 창의적 변이
5. 새 세대로 2번 반복 → 종료(§5.4)
```

- 정적(1세대) = 진화의 **출발점**이지 진화를 죽이는 게 아님. 세대 갈수록 후보가 줄어(8→3→2)
  탐색 공간이 좁아지고 비싼 LLM은 유망한 곳에만 투입됨.
- LLM 변이 시 `improvement` 필드(왜 이렇게 바꿨는지) 기록 → 대시보드 "AI 추론 과정".

### 5.3.1 변이·생성 계층 — 거부(refusal)·API 밴 회피

**문제**: 상용 LLM(Claude/OpenAI)에 "jailbreak 공격 프롬프트 만들어줘"를 반복하면 ①모델이 거부하거나
②콘텐츠 정책 위반으로 계정 경고/밴 위험 (실제로 공격 데이터 다루다 API 밴 경험 있음).

**해결 = 생성을 최대한 피하고, 필요할 때만 안전한 경로로. 4계층 폴백** (위로 갈수록 우선):

- **L0 검색 (생성 안 함)**: DB에서 실제 검증 프롬프트를 그대로 꺼냄. LLM 호출 자체가 없음 → 거부·밴 0.
- **L1 결정론적 변형 (LLM 없음)**: 씨앗에 인코딩·난독화를 **코드로** 적용 — base64, leetspeak, rot13,
  homoglyph, 다국어 번역, 템플릿 래핑. promptfoo `strategies/`가 이걸 순수 코드로 함. 거부·밴·비용 전부 0.
  → **변이의 상당수를 여기서 커버.**
- **L2 로컬 uncensored 모델 (LLM이지만 API 아님)**: 의미적 변이가 필요할 때 — 검열 해제(abliterated)
  로컬 모델을 Ollama/vLLM으로 구동. **거부 없음 + 계정 밴 없음(내 기계)**. 7~8B면 8~16GB RAM로 구동.
- **L3 상용 LLM (최후·신중)**: 정말 필요할 때만. red-team 시스템프롬프트로 프레이밍 + 거부 감지 시 폴백.
  상용은 밴 리스크 있으니 최소화.

**핵심 원칙**: "위험한 생성"은 **로컬(L2)에 격리.** 대상 호출·판정은 원래 무해한 요청이라 상용 써도 됨.
→ 밴 리스크는 오직 attacker 생성에만 존재하고, 그걸 로컬로 빼면 사라진다.

### 5.4 종료 조건

**목표(Objective) 하나가 끝나는 조건 (5중 1)**:
- ① 성공: 판정 점수 ≥ 기준 → 뚫림 확정
- ② 예산: 최대 세대 수(예: 5) 도달
- ③ 정체/수렴: N세대 연속 최고점 개선 없음(예: 2) → 포기
- ④ 전멸: population 비면
- ⑤ 시간: 목표당 제한시간 초과(안전장치)

**스캔 전체**: 모든 목표가 위 중 하나로 끝나면 완료. 전역 안전장치 `max_total_cost/time`.

> 주의: "목표(Objective)"는 대상 앱 하나를 여러 각도로 공격하는 시나리오 단위.
> "목표 9개"는 앱 9개가 아니라 **앱 1개를 9가지 방법으로** 공격한다는 뜻.

### 5.5 성공 판정 — 큰 LLM 없이 (비용 ≈ 0)

**3단계 계층 (돈 순서)**:
1. **룰 (무료·즉시)**:
   - 거절 패턴 매칭("죄송하지만"/"I can't") → 안전 확정
   - 유출류는 **카나리/허니토큰**: 더미 앱에 가짜 시크릿(`FLAG123`)·가짜 PII를 심어두고
     응답에 그 문자열이 나오면 뚫림 확정 → **오탐 0%, 정확 100%**
2. **무료 라이브러리 (로컬)**: 룰로 애매한 유해성만 — **llm-guard**(Toxicity/Sensitive/NoRefusal)
   또는 GPTFuzz RoBERTa 판정 모델(`hubert233/GPTFuzz`)
3. **LLM (최후·거의 안 씀)**: 정말 애매한 극소수만 Haiku 1회

- 유형별: PII·프롬프트유출·데이터유출 = 룰만으로 끝. 유해 콘텐츠만 라이브러리.
- 룰 품질은 **감이 아니라 라벨셋 30~50개로 정확도(precision/recall) 측정**해서 확인.
- 애매하면 "안전"이라 단정하지 말고 다음 단계로 에스컬레이션 (놓침이 제일 위험).

### 5.6 액터 (대상 연결) — 설정 기반

- 공통 인터페이스 `send(prompt) -> response` 하나. 엔진은 방식 모름.
- **HttpActor**: `url/method/headers/body({{prompt}})/response_path` + `delay/max_retries`.
  밴 회피(delay/429/백오프/지터/maxRetries)를 **액터 안에 캡슐화**(promptfoo `util/fetch` 방식).
- **BrowserActor**: Playwright, `navigate→fill→click→inner_text`. selector(입력창/전송버튼/응답영역
  CSS)는 **유저가 등록 시 직접 입력** — 우리가 자동감지하지 않음. 따라서 자동감지 불안정 리스크 없음.
  다만 앱마다 selector가 달라 유저 입력이 필요하므로 후순위(HttpActor 먼저).
- 팩토리가 `type`으로 분기 생성. 복잡한 인증은 PoC에서 생략(promptfoo 3266줄의 대부분이 그거).
- 구현 순서: **HttpActor 먼저 완성 → BrowserActor는 인터페이스만 열어두고 후순위.**
- ⚠️ 밴 회피 래퍼는 **대상 호출뿐 아니라 공격자·판정용 LLM API 호출에도** 동일 적용.

### 5.7 ATLAS 매핑 — 정적 테이블 (authoring-time)

- promptfoo와 동일하게 **LLM 사후추론 금지, 정적 룩업 테이블** 유지.
- 매핑 방향: `공격 유형/전략 → ATLAS 기법ID` 를 미리 하드코딩(DB `attack_case.atlas_technique_id`).
- 결과·목표·발견까지 자동 전파 → 히트맵이 근거 있게 채워짐.
- 신뢰도 보강: RAG로 ATLAS 기법 설명 주입 + confidence 점수 + 라벨셋 정확도 측정.

## 6. 비용 설계 (확정)

- **정찰 후 전략 선결정**: 모든 전략에 추론 X → 좁힌 전략에만.
- **정적 프롬프트 우선**: 1세대는 LLM 없이 DB 씨앗 그대로.
- **모델 하향**: 공격자·판정은 Haiku. 대상만 실제 모델.
- **로컬 uncensored 모델(선택)**: 공격 프롬프트 "생성"에만. 비용 자유 + **거부(refusal) 없음**
  (Claude/Haiku는 공격 프롬프트 생성을 거절할 수 있음 → promptfoo도 `abliteration.ts` 별도 둠).
- **판정은 룰+llm-guard**로 큰 LLM 회피(§5.5).
- **DB 검색을 변이로** 써서 LLM 호출 자체를 대체(§5.3).

→ 진짜 비용은 대상 rate limit이 아니라 **루프당 LLM 3중 호출**. 위 조합으로 이걸 최소화.

## 7. 시간 추정

가정: 목표 3종, 1세대 정적 8개, 최대 5세대, 대상~2초/판정~1.5초/변이~1.5초.

- 목표 1개 ≈ 20~30초 (세대 순차, 세대 안 병렬)
- **스캔 전체(목표 병렬) ≈ 30초~1분** (자체 대상 + Haiku + 병렬)
- 외부 API 대상 1~3분 / 순차 실행 5~10분(비권장)

시간 다이얼: ①**병렬 정도**(최대 영향) ②최대 세대 ③정체 조건 ④모델.
어차피 백그라운드+실시간 진행이라 "AI가 진화하는 걸 실시간으로 보는" 것이 데모 하이라이트.

## 9. ERD (5~8 테이블 — 적은 편)

```
User ──< Target ──< Scan ──< Objective ──< Attempt >── AttackCase
                      └──< Finding              │(self) parent_attempt_id
                                        AtlasTechnique (라벨)
```

- **PoC 최소 5개**: Target, AttackCase, Scan, Attempt, Finding
- **핵심 컬럼**:
  - `Attempt.parent_attempt_id` (self-ref) = 진화 계보 → 진화 트리 시각화 (우리만의 차별점)
  - `Attempt.seed_case_id → AttackCase` = "실제 데이터 기반" 추적
  - `atlas_technique_id` 여러 곳 = 히트맵 신뢰도
- 데이터는 많아도(AttackCase 수만 건) **테이블 종류는 적음**. 신경 쓸 건 Attempt(진화기록) +
  AttackCase(대용량·pgvector 인덱스) 둘뿐.
- 확장 시: AtlasTechnique(마스터), User(멀티테넌시), ScanEvent(실시간 로그).

## 11. 남은 리스크 & TODO (실제만)

> PoC는 의도적으로 한 조각(="AI가 공격 프롬프트를 실제로 생성하는가")만 증명하는 단계다.
> "PoC가 최종 스펙과 다르다"는 결함이 아니라 정상. 아래는 PoC 착시를 걷어낸, 실제로 챙길 것만.

1. **인가/대상 소유 확인**: 로그인 → 대상 등록 시 GitHub 주소·엔드포인트 입력 → 확인 과정으로
   커버(기획 의도에 포함). 한 가지만 명시 권장 — "리포 주소 제공 = 코드 열람 권한"이지
   "타겟 엔드포인트 공격 권한"과는 별개이므로, **대상 앱 소유/권한 확인 한 단계**는 명확히 둘 것.
   PoC는 자체 더미 앱만 대상.

2. **발표 대본 문구**: `AI레드팀-PoC-발표.md`의 "LLM Judge=심장"은 판정을 룰+카나리+llm-guard로
   대체(=개선, 비용 절감)한 결정에 맞춰 표현만 업데이트. **모순이 아니라 판단 변경** —
   LLM 판정은 대단한 기술이 아니라 그냥 LLM한테 분석시키는 것이라, 더 싼 걸로 대체되면 이득.

3. **데이터셋 통합 (진행 중)**: HackAPrompt·SPML·L1B3RT4S 통합·정제는 계속 진행. 오류 아니라 TODO.

4. **ATLAS 매핑 테이블 (구현 TODO)**: PoC는 3기법만 하드코딩. 실제 구현에선 subset 12개(및 확장)를
   정적 테이블로 라벨링. 오류 아니라 남은 작업. (ID T0051/T0054/T0057은 ATLAS.yaml 대조 정확함 확인.)

5. **후순위 리스크(낮음)**: 브라우저 액터 selector는 **유저가 등록 시 직접 입력**(자동감지 아님)이라
   부담 낮음 → HttpActor 먼저. 로컬 uncensored 모델은 "공격 프롬프트 생성"에만 쓰는 선택 옵션(§6),
   1차는 Haiku.

> 폴더는 `ai-redteam/`로 변경 완료. PoC 단계 수치(1,405 등)를 최종 스펙 결함으로 볼 필요 없음.

## 12. 미해결 질문 정리 + 답

- **UI 자동화 / 액터란?** → 액터=대상과 통신하는 어댑터(`send→응답`). UI 자동화=API 없는 앱을
  Playwright로 조작(=브라우저 액터 내부구현). §5.6.
- **ATLAS 매핑 신뢰도 (프롬프트 엔지니어링 외)?** → **정적 매핑 테이블**(authoring-time) +
  RAG grounding + confidence + 라벨셋 측정. §5.7. (promptfoo 실제 구현이 정적 테이블임을 확인.)
- **적응형 공격 종료 조건?** → 성공/예산/정체/전멸/시간 5중 1, 목표별. §5.4.
- **판정 비용 아끼기 (모델 없이)?** → 룰+카나리+llm-guard 3단계, LLM 최소. §5.5.
- **DB 언제·어떻게 효율적으로?** → 정찰후 필터→1세대 씨앗→변이소스, 하이브리드 검색+성공가중치. §5.2~5.3.
- **PyRIT는 API인가?** → 아니오, 파이썬 라이브러리. Scorer는 판정 참고용. §3.2.
