로그인 / 인증 시나리오 핵심 축

로그인 여부 = 공격 표면 자체가 달라진다. 비로그인은 탈옥·프롬프트 유출 정도지만, 로그인하면 타인 PII 조회·도구 실행(이체·메일)까지 열린다. → 상태별로 나눠 스캔해 비교하는 게 리포트의 핵심.

⚠️ 비밀번호·시크릿은 값이 아니라 env 변수 이름으로 입력한다 (필드명 *_env). DB 평문 저장 금지 — 확정된 보안 규칙.

스캔 시 scans.config.auth_context로 "어느 역할로 공격할지" 고른다. 여기선 역할별 자격증명을 등록.

▶ inject — 토큰을 어디에 붙일지 기본 header/Authorization
▶ session — 멀티턴/상태유지 선택 · 후순위

응답에서 세션ID를 뽑아 다음 요청에 재주입(대화 상태 유지). 크레센도(멀티턴) 공격용 — 단일턴 데모엔 불필요.

Browser 설정 config

API가 없는 채팅 화면용. Playwright가 입력창에 타이핑→전송→응답 추출. 셀렉터를 사람이 찾아 넣어야 해 HTTP보다 번거롭다.

🔍 CSS 셀렉터 찾는 법 (개발자도구)

  1. 타겟 채팅 페이지에서 F12 (Mac은 ⌥⌘I) 눌러 개발자도구 열기
  2. 왼쪽 위 요소 선택 아이콘(⌖ 화살표) 클릭
  3. 페이지에서 원하는 요소(입력창 등) 클릭 → HTML이 하이라이트됨
  4. 하이라이트된 줄 우클릭 → Copy → Copy selector
  5. 복사된 값을 아래 칸에 붙여넣기
input_selector입력창(텍스트 치는 곳)을 선택 → copy selector submit_selector전송(▶) 버튼을 선택. 버튼 없고 Enter로 보내면 비워둠 output_selector챗봇 답변 말풍선을 선택. 보통 마지막 답이라 :last-child가 붙음
▶ 로그인 / 세션 — 브라우저는 이렇게 다름 선택 · 후순위
브라우저는 실제 크롬처럼 쿠키를 자동으로 들고 다녀서, 한 번 로그인하면 스캔 내내 로그인 상태가 유지된다. 멀티턴 대화도 같은 탭에서 이어지니 세션이 공짜로 유지됨. → HTTP의 auth·session 필드는 브라우저엔 안 쓰이고, 대신 아래 둘 중 하나를 쓴다.

이미 로그인한 브라우저에서 쿠키/스토리지를 내보내 붙여넣으면 그 상태로 시작. (Playwright storageState JSON)

스캔 시작 시 로그인 페이지에서 아이디·비번을 타이핑→로그인하고 진행. 셀렉터를 또 찾아야 해 무거움.
