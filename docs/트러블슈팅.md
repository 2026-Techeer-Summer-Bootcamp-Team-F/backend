### 14. 공격 코퍼스 다중 소스 통합 적재 + dedup (로컬 3소스)
- **날짜**: 2026-07-08
- **분류**: 데이터
- **문제**: (1) 탈옥 프롬프트 원문을 대화창에 출력하려다 안전필터에 걸려 API 에러 반복 발생. (2) 로컬 소스가 3종(jailbreak_prompts.csv / latest_jailbreaks_2026.csv / l1b3rt4s/*.mkd)인데 1종만 적재돼 있었음. (3) 키워드 3분류가 탈옥을 data_leakage로 오분류. (4) 길이 15자 컷이 짧지만 유효한 프롬프트까지 제거. (5) l1b3rt4s가 56→6으로 급감해 파싱버그 의심.
- **원인**: (1) 응답에 원문 프롬프트를 그대로 실음. (3) in-the-wild 소스가 전부 탈옥 라벨인데 "system prompt" 등 단어로 오버라이드. (5) 실은 버그 아님 — Pliny L1B3RT4S 내용이 다른 두 소스에 이미 중복(exact 45 + near 5, near건도 latest-2026이 1500자로 자른 동일 프롬프트).
- **적용한 기술/방식**: ①원문은 대화창에 안 뿌리고 **스크립트가 파일→DB 직접 처리 + 개수·통계만 보고**. ②`corpus_ingest.py`를 다중 소스로 리팩터(로더 3개: CSV 2 + 마크다운 `# 헤딩` 파서 1) → **3소스 합쳐 교차 dedup**(정규화+md5 exact, 토큰 자카드≥0.85 near). ③분류는 옵션(a) 채택 = 3소스 모두 `jailbreak/AML.T0054`로 통일하고 원 라벨(모델·기법·벤더)은 `tags` JSON에 보존(정보 무손실, 정밀 재분류는 임베딩 단계로 이연). ④길이 컷 → **3단어 미만만 컷**으로 완화(성공여부는 `verified`로). ⑤near-dedup 소스쌍·자카드·길이를 추적 출력해 오탐 아님을 데이터로 확인. ⑥py3.9 호환: `datetime.now(timezone.utc)`. 검증 조인 컬럼명(`atlas_techniques.id`) 교정.
- **결과**: 해결 — 1,517 raw → 필터 1,491 → 교차 dedup **1,224건 적재**(in-the-wild 1167 / latest 51 / l1b3rt4s 6), ATLAS 마스터 조인 고아 0. "l1b3rt4s 고유 = 6개"를 데이터로 확정.
- **관련 파일/커밋**: `app/backend/corpus_ingest.py`, `app/backend/corpus.db`, `기획/docs/벡터DB-적재계획.md`
- **(이어서) HF 소스로 유형 다양성 보강**: 코퍼스가 전부 jailbreak라 유형 필터 데모 불가 → HF 3소스(deepset·xTRam1 safe-guard=injection label==1, Lakera gandalf=leakage) 추가. **문제**: homebrew 파이썬 pip 깨져 `datasets` 설치 불가 + HF API **429(rate limit)** 반복. **방식**: `datasets` 없이 **datasets-server `/rows` API를 HTTP로 직접**(`fetch_hf.py`, stdlib urllib) → `hf_cache/*.jsonl` 캐시(네트워크 1회, 재적재는 오프라인). 429는 **쓰로틀 0.7s/페이지 + 6·12·18s 백오프**로 해결. 라벨 뒤집힘 방지 위해 실제 행 샘플로 `label==1`=injection 확인 후 필터. **결과**: 최종 **4,867건**(prompt_injection 2,664 / jailbreak 1,224 / prompt_leakage 979), 6소스, 조인 고아 0 → **유형 다양성 확보**. 상세 재현매뉴얼 = `기획/docs/벡터DB-적재-실행기록.md`. 다음: 임베딩+pgvector.
- **관련 파일(추가)**: `app/backend/fetch_hf.py`, `app/backend/atlas_ingest.py`, `기획/docs/벡터DB-적재-실행기록.md`

- **분류**: 설계 · 문서

- **결과**: 해결 — 정합본(`ERD-완전정리.md`·`API-명세.md`)이 단일 기준이 되고, 옛 문서는 배너로 오용 차단.

### 7. ERD를 손으로 그리면 DB 스키마와 어긋남

- **결과**: 해결 — 문서·DB 100% 일치, 클라우드 ERD는 Import만 하면 됨.
- **관련 파일/커밋**: `app/backend/gen_erd.py`, `docs/schema.sql`, `docs/erd.dbml`, `docs/ERD.md §5`

### 6. 공격 프롬프트 생성 시 상용 LLM이 거부하거나 계정이 밴될 위험
- **날짜**: 2026-07-04
- **분류**: 엔진 · 설계
- **문제**: 탈옥/인젝션 프롬프트를 만들려고 상용 LLM(예: Haiku)에 시키면 거부되거나, 반복하면 계정 제재 위험.
- **원인**: 상용 모델의 안전 정책 — 공격 콘텐츠 "생성"을 막음.
- **적용한 기술/방식**: 변이 경로를 **4계층 폴백**으로 설계 — L0 검증코퍼스 벡터검색(생성 안 함, 무료) → L1 결정론적 인코딩(base64/leetspeak 등, 무료) → L2 **로컬 uncensored LLM(Ollama)로 생성 격리**(거부·밴 없음) → L3 Haiku(극소수만). 위험한 "생성"은 로컬로 빼서 상용 API에는 "분석"만 시킴.
- **결과**: 해결(설계 확정) — 상용 API 밴 리스크 제거, 비용도 최소.
- **관련 파일/커밋**: `app/backend/app/engine/mutators.py`, `docs/ARCHITECTURE.md §4·§11.2`

### 5. ATLAS 기법 매핑을 LLM 추론으로 하면 비싸고 신뢰도 낮음
- **날짜**: 2026-07-03
- **분류**: 엔진 · 설계
- **문제**: 성공한 공격을 MITRE ATLAS 기법ID에 매핑해야 하는데, 매번 LLM에게 "이건 무슨 기법?" 물으면 비용↑·재현성↓·오답 위험.

- **적용한 기술/방식**: **정적 룩업 테이블**(authoring-time 라벨). `(attack_type, strategy) → [ATLAS ID]` 딕셔너리로 상수 매핑, 런타임 LLM 추론 금지. (promptfoo 실제 구현 `frameworks.ts`도 정적 테이블임을 확인해 근거로 삼음.)

### 4. 반복 공격 발사 중 rate-limit(429)·밴에 걸림
- **날짜**: 2026-07-04
- **분류**: 엔진
- **문제**: 진화 루프가 대상 엔드포인트에 프롬프트를 계속 쏘면 429(rate limit)나 일시 차단에 걸려 스캔이 죽음.
- **원인**: 짧은 간격의 대량 요청 + 동시 재시도 storm.
- **적용한 기술/방식**: 밴 회피를 **HttpActor에 캡슐화** — 429는 `Retry-After` 헤더 파싱 + 랜덤 지터(0~5초), 502/503/504는 지수 백오프(1→2→4→8초), 진짜 밴(insufficient_quota 등)은 즉시 실패. `max_retries`로 상한. (분산 시 Redis 카운터로 워커 간 rate-limit 좌표 공유하는 프로덕션 설계 포함.)
- **결과**: 해결 — 폭주 방지, 스캔이 중단 없이 진행.
- **관련 파일/커밋**: `app/backend/app/engine/actor.py`, `docs/ARCHITECTURE.md §7`

### 3. 뚫림 판정을 큰 LLM으로 하면 비용이 폭발함
- **날짜**: 2026-07-03
- **분류**: 엔진 · 설계
- **문제**: 공격 성공 여부(뚫렸나)를 매 시도마다 대형 LLM judge로 판정하면 스캔당 호출 수천 건 → 비용·지연 폭발. 초기 기획의 "LLM Judge=심장" 전제가 비현실적.
- **원인**: 시도마다 판정이 필요한데 LLM 판정은 비쌈.
- **적용한 기술/방식**: **판정 3계층** — Tier1 룰(거절패턴 정규식 + **카나리/허니토큰 문자열 매칭**: 더미앱에 `FLAG` 심어두고 응답에 그 문자열이 나오면 뚫림 100% 확정, 오탐 0%) → Tier2 llm-guard(로컬 분류모델) → Tier3 Haiku(정말 애매한 1~3%만). 즉 대부분을 **문자열 매칭으로 공짜 판정**.
- **결과**: 해결 — 판정 비용 사실상 0, 카나리 매칭은 거짓양성 없음.
- **관련 파일/커밋**: `app/backend/app/engine/judge.py`, `docs/ARCHITECTURE.md §6`
